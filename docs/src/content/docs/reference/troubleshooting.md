증상에 해당하는 항목을 찾아보세요. 시트의 값이 잘못되어 생기는 오류는 [검사와 문제 해결](../../tools/problems/)에 따로 정리되어 있습니다.

## 설치와 빌드

### 생성된 코드가 컴파일되지 않습니다

`MemoryPack`이나 `MessagePack`을 찾을 수 없다는 오류라면 직렬화 라이브러리가 프로젝트에 없는 것입니다. HolySheet 창 위쪽에도 경고가 표시됩니다. [설치하기](../../start/install/#2-직렬화-라이브러리-추가하기)를 따라 추가하세요.

### 빌드했는데 파일이 생기지 않습니다

상태 표시를 확인하세요.

- **실패**라면 오류가 있어 아무것도 쓰지 않은 것입니다. 아래쪽 **문제** 목록을 확인합니다.
- **검사 완료**라면 **검사**만 누른 것입니다. 검사는 코드와 데이터를 쓰지 않습니다. **전체 빌드**를 누르세요.
- **최신 상태**라면 바뀐 내용이 없어 다시 쓰지 않은 것입니다.

### ‘No table was found’ 오류가 납니다

읽을 테이블이 하나도 없다는 뜻입니다.

- **설정 → 소스**의 경로에 실제로 시트 파일이 있는지 확인합니다.
- 시트의 위쪽 세 줄이 타입, 이름, 설명 순서인지 확인합니다.
- 탭 이름이 `#`이나 `~`로 시작하면 읽지 않습니다.

### 시트에 추가한 행이나 열이 보이지 않습니다

- 행의 A열, 열의 헤더가 `#`이나 `~`로 시작하면 제외됩니다.
- 타입과 이름이 모두 빈 열은 읽지 않습니다. 이때 검사가 경고를 표시합니다.
- Excel에서 파일을 저장했는지 확인합니다. 저장하지 않은 내용은 읽을 수 없습니다.

### 빌드가 ‘cannot identify it as its own output’으로 멈춥니다

출력 폴더에 HolySheet가 만들지 않은 파일이 같은 이름으로 있습니다. 덮어쓰지 않으려고 멈춘 것이니, 그 파일을 옮기거나 **설정 → 출력**에서 다른 폴더를 지정하세요.

### 선택 빌드를 누르면 전체 빌드를 하라고 합니다

저장소에서 다른 사람의 빌드 결과를 받은 직후이거나, 이 컴퓨터에서 빌드한 적이 없을 때 나타납니다. **전체 빌드**를 한 번 하면 다시 쓸 수 있습니다. [선택 빌드가 거부될 때](../../tools/partial-build/#선택-빌드가-거부될-때)

## 시트의 값

### 배열에 넣은 `1,000`이 값 두 개로 읽힙니다

Google Sheets가 숫자에 천 단위 쉼표를 붙여 보여 주고 있고, 그 쉼표가 배열 구분자로 읽힌 것입니다. 그 열의 셀 서식을 **일반 텍스트**로 바꾸세요.

### 소수가 다른 값으로 읽히거나 오류가 납니다

소수점은 항상 마침표(`.`)로 적습니다. `1,5`가 아니라 `1.5`입니다.

### ‘cannot be used as a field name’ 오류가 납니다

필드 이름과 테이블 이름은 C# 코드의 이름이 되므로 공백이나 기호(`-`, `.`, `%`)를 쓸 수 없고, 숫자로 시작할 수 없습니다. `Max HP`는 `MaxHp`로, `2ndSkill`은 `SecondSkill`로 고치세요. 사람이 읽을 이름은 설명 행에 적습니다.

## Google Sheets

### 문서를 읽지 못합니다

- **공개 링크**를 쓴다면 문서의 공유 설정이 ‘링크가 있는 모든 사용자’인지 확인합니다.
- **서비스 계정**을 쓴다면 문서를 서비스 계정의 이메일 주소에 공유했는지, 키 파일의 경로가 맞는지 확인합니다.
- **구글 드라이브 폴더**는 공개 링크로 읽을 수 없습니다. API 키나 서비스 계정을 쓰세요.

### 인터넷이 없는 곳에서 빌드해야 합니다

모든 Google 소스에 **스냅샷 폴더**를 지정하고 온라인에서 한 번 빌드해 두면, 이후에는 **오프라인**을 켜고 빌드할 수 있습니다. [오프라인으로 빌드하기](../../tools/google-sheets/#오프라인으로-빌드하기)

## 게임 실행

### Android나 WebGL에서 테이블을 불러오지 못합니다

이 플랫폼에서는 `StreamingAssets`의 파일을 바로 열 수 없습니다. `GameTables.Load` 대신 `await GameTables.LoadAsync`를 쓰세요. [Android와 WebGL](../../runtime/loading/#android와-webgl)

### `SchemaMismatch` 오류가 납니다

데이터 파일이 지금의 생성 코드와 다른 열 구성으로 빌드됐습니다. 시트에 열을 추가하거나 타입을 바꾼 뒤 코드와 데이터 중 한쪽만 갱신됐을 때 생깁니다. 다시 빌드하고, 생성된 코드와 데이터 폴더를 함께 반영하세요.

### `HashMismatch` 오류가 납니다

데이터 파일이 빌드한 뒤에 바뀌었습니다. 일부 파일만 복사했거나, 파일을 직접 고쳤거나, 서로 다른 빌드의 파일이 섞였을 때 생깁니다. 데이터 폴더를 통째로 다시 빌드해 넣으세요.

### `SignatureInvalid` 오류가 납니다

서명을 켠 프로젝트에서 서명이 없거나 다른 키로 서명한 데이터를 불러왔습니다. 개인 키가 있는 곳에서 다시 빌드하세요. [변조 감지와 서명](../../runtime/integrity/#서명)

### 시트를 고쳤는데 게임의 값이 그대로입니다

- 시트를 고친 뒤 **빌드**했는지 확인합니다. `holysheet watch`를 실행하면 저장할 때마다 빌드합니다.
- 실행 중인 게임에 바로 반영하려면 `Load` 대신 `Watch`를 써야 합니다. [실행 중에 다시 불러오기](../../runtime/reload/)
- 이전에 꺼내 둔 행은 옛 값을 가지고 있습니다. `watcher.Current`에서 다시 꺼내세요.
